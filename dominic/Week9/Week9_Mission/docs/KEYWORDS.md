# 9주차 핵심 키워드

## Swagger / OpenAPI
OpenAPI는 API 요청·응답·인증을 기술하는 명세이며, Swagger UI는 이를 문서와 실행 화면으로 보여줍니다.
코드의 데코레이터를 기반으로 생성해 문서와 구현의 차이를 줄일 수 있습니다.

## 단위 테스트
가짜 Repository로 외부 의존성을 대체하고 서비스 한 단위의 판단을 검증합니다.
중복·권한 오류의 code와 저장 호출 여부를 빠르게 확인할 수 있습니다.

## 통합 테스트
여러 계층을 연결해 실제 HTTP 요청부터 인증·검증·서비스·DB 저장까지 확인합니다.
이번에는 sql.js 메모리 DB로 테스트 데이터를 격리하고 응답과 DB 상태를 함께 검증했습니다.

## Mock, Stub
Stub은 미리 정한 값을 반환하고, Mock은 호출 횟수·인자 등 상호작용도 확인하는 테스트 대역입니다.
jest.fn()으로 중복 조회 결과를 준비하고 save가 호출되지 않았는지 검증했습니다.

## given-when-then
given은 상황 준비, when은 동작 실행, then은 결과 검증 단계입니다.
테스트 이름과 본문에 상황·행동·기대 결과를 드러내면 실패 원인을 파악하기 쉽습니다.

## 회귀 테스트
기존 동작이 코드 변경으로 깨지지 않았는지 반복해서 확인하는 테스트입니다.
중복 검사·트랜잭션을 제거했을 때 실패하고 복원 후 통과하는 실험으로 검증력을 확인했습니다.
